GovSetu Interoperability layer for government services
Prototype build · not connected to live department systems

One identity. Every department. No repeated paperwork.

Aadhaar, DigiLocker, GST and state e-Governance portals each speak a different data language today, so citizens resubmit the same documents at every counter. GovSetu sits between them as a translation layer, so a request made once reaches every department that needs it.

SIH26129 · System Integration & Interoperability Among Government Digital Platforms · Team Ctrl Alt Destroy

The gap between departments, and what closes it

Every portal already works on its own. The friction is at the seams between them.

Today, without interoperability

  • Citizens resubmit identity and address proof at every department counter.
  • Cross-department services stall waiting for manual verification.
  • Each new integration is a custom, point-to-point build.
  • No shared view of where a request is stuck, or why.

With GovSetu in between

  • A lightweight API gateway translates protocols and formats in real time.
  • An AI schema-mapping model auto-detects matching fields across databases.
  • Legacy systems connect through thin adapters — no core rewrite.
  • A live dashboard flags mismatches and failed handshakes as they happen.

How a request moves through the system

The same four-step path every request follows, whether it is met by a matching field or not.

01

Citizen request

Submitted once through the unified portal, with single sign-on.

02

Schema check

The AI mapper checks whether fields and protocols already correspond.

03

Route or transform

A match routes straight to the department system; a mismatch goes through the adaptive transform layer.

04

Aggregated response

Results are combined and returned to the citizen dashboard as one status.
